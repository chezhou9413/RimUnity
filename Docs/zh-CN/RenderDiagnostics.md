# 一次性场景与显存诊断

在黑屏现场开启开发者模式，打开调试操作菜单，搜索 **复制调试信息**（`RimUnity` 分类）。点击一次后保持游戏运行约三秒；主菜单和存档内均可使用，不要求生成粒子或开启上帝模式。

完成后自动复制报告，并将完整文本保存到游戏配置目录的 `RimUnityReports/render-debug-时间.txt`。剪贴板超过四百万字符时只截断复制内容，末尾注明完整文件位置；磁盘报告保留完整内容。剪贴板失败时日志仍显示文件位置。

## 报告内容

- 操作系统、进程内存、GC、显示及兼容层硬件信息。兼容层字段可能是占位值，判断设备时应优先使用原生 Vulkan GPU 描述。
- 当前显卡、驱动、可用设备、扩展、交换链格式、设备限制，以及 HDR/深度/压缩格式支持。
- VMA 显存堆预算、驱动/分配器用量、宿主按用途统计的分配、最大分配项、系统内存迁移和延迟释放。
- 采集前后的资源清单、共享 owner、缓存资源、纹理格式、CPU 数据和 GPU 驻留、相机及有效 Bloom 设置。
- 三秒内观察到的地图提交、队列切片、HDR/Bloom 和原生合成调用；有限数量的真实绘制项和其 Shader/纹理状态。
- 程序集身份、文件路径、MVID 和关键文件 SHA256；启用模组和加载目录；渲染相关 Harmony 补丁。
- 启动期及近期错误、警告、最新日志和磁盘日志尾段。截断或读取失败都会明确说明。

## 边界

采集不读取存档内容、不上传网络、不强制 GC、设备等待、纹理恢复或清理，也不修改渲染设置。用户目录路径在普通文本和 JSON 转义文本中均替换为 `<USER>`。它只观察已有缓存，不能保证检查到每个传递依赖文件。

CPU 调用完成、GPU 图像存在，不等于最终像素正确。报告不读取 GPU 描述符或最终像素；跟踪的分配字节也不能直接当作当前专用显存驻留量。主菜单没有地图阶段可能是正常情况，不能把缺少采样一概解释为成功。

元数据复制器按运行中的宿主绑定公开值成员，避免硬编码已被移除的 `MeshDrawFrame` 可选 getter。报告中记录绑定成员和宿主 MVID。具有只读引用调用的原生合成方法不使用 Harmony detour，改在现有桥接调用位置记录状态。

## 定向验证

```powershell
dotnet run --project Tools/RenderDiagnosticsTests/RenderDiagnosticsTests.csproj -- "1.7/Assemblies/RimUnity.dll" "<GameRoot>" "<HarmonyPath>/0Harmony.dll"
```

覆盖读取异常隔离、采样容量与关闭状态、路径脱敏、剪贴板截断提示、属性/字段两种宿主布局、资源引用保持、当前实际宿主元数据初始化，以及诊断补丁的实际安装和卸载。实机画面与黑屏复现仍需要游戏内验收。

# 首次特效卡顿采集

开发者菜单中搜索 `卡顿诊断`，所有入口位于 `RimUnity` 分类。适用于首次生成某个粒子特效时的瞬时卡顿，也可以在主菜单采集。

## 特效性能测试场

在已加载地图的游戏中启用开发者模式，打开调试动作菜单的 **RimUnity → 特效性能测试场**。工具会建立 96×96 的临时棋盘地图并暂停原版游戏 Tick；不需要额外 DLC。

测试地图使用无动植物的专用生态，保持晴天和 21℃，不依赖世界地块的植物生长率采样。相机和控制面板在地图绘制初始化后开启；创建失败会先记录原始异常，再清理临时地图已经建立的资源。

带有缺失脚本等导出警告的特效会在选择列表中标明原因；选中资源的原始警告写入 TXT、JSON 报告的 `AssetWarnings`。其脚本行为可能不完整，性能结果不能视为完整源特效的性能。Animator 遇到当前预制体不存在的动画节点或组件时，只跳过这些目标的曲线并按剪辑去重提示，保留有效轨道；补齐层级后可调用 `Rebind()` 重新绑定。这不会恢复源资源中已经缺失的节点或脚本。

1. 在“选择特效”页按模组名或逻辑路径筛选，勾选要测试的特效。只索引已启用模组中含 `RimUnity.ParticleSystem` 的导出预制体，读取描述时不会提前实例化或加载贴图。
2. 在“播放控制”页默认勾选“固定数量常驻循环（稳定负载）”。设置固定实例总数、填满后的预热时间、分布半径、整体倍率和 X 轴旋转。建议先取消全部勾选，只选一个特效，使用 20 个实例、半径 8 格、倍率 1、预热 10 秒。半径 0 会让全部实例重叠，可另作像素覆盖压力测试。选中多个特效时按列表顺序分配给实例，总数不得少于所选特效数。
3. 点击“应用参数并播放 / 重新开始”。固定模式分帧填满实例后，先预热，再自动采样。测试克隆的普通发射器被设为循环，事件子发射器保持原有关系；每个系统使用固定种子，重启时恢复相同初始位置和种子。频率、实例最长寿命不参与固定模式，稳态期间不持续创建/销毁实例。脚本自行禁用或销毁根对象会停止测试，不静默补充实例。未勾选固定模式时保留原有按频率创建、按寿命销毁的测试方式，应用参数后立即采样。
4. 在“采样与报告”页调整采样时长，或停止、重新采样、导出。默认 60 秒，可调 10～300 秒；固定最多保留 36000 帧，到时或达到容量会自动停止并导出。采样停止后可以继续观看特效。
5. 可折叠控制面板，减少界面绘制对测量的影响。关闭窗口、退出开发者模式、切换地图或离开游戏会话会停止测试和采样；正常关闭返回原地图并删除临时地图。测试期间不能保存，退出后恢复保存功能。

常规报告保存在游戏配置目录的 `RimUnityReports`，文件名前缀为 `effect-lab-`：

- `.txt`：测试条件，平均帧率，P50/P95/P99/最大帧间隔，慢帧数量，托管分配、GC、工作集变化，以及各资源实例创建的首次、平均、最大耗时。
- `.json`：测试参数、所选资源、程序版本标识、完整逐帧样本与按资源汇总的创建耗时。
- `.frames.csv`：逐帧时间、进程分配、GC、测试实例/系统/粒子数、地图提交项、内存、实际创建数、限流帧数及详细探针开关状态。

### CPU 阶段与分配定位（schema 8，CPU 阶段 schema 3）

schema 8 增加全局粒子来源：每帧区分活动系统、测试根节点及其所有动态子节点、背景系统、粒子数量、带启用 Renderer 的系统和空系统，并按主相机图层与 Canvas 条件统计候选。原来的 `Systems/Particles` 仍来自实例创建时记录的组件列表；新字段 `ParticlePopulation.OwnedSystems` 包含后续动态子节点，二者的差异本身就是诊断线索。候选数量包含空系统，不等于绘制提交次数；CPU Renderer 阶段还可能含离屏和 UI 调用，不能机械一一对应。

TXT/JSON 在开始、结束边界列出背景对象以及测试场空 Renderer 的实例 ID、名称、根对象、层级路径、粒子数、图层和 Canvas 状态。两类清单分别最多 128 条，截断明确标记，不截断全局数值。每帧只扫描数值，不创建名称字符串；身份清单只在计时前后构建。`.population.csv` 与其他逐帧 CSV 按 `frame` 对齐；`Frames[].ParticlePopulation` 保留相同数值。所有权按当前层级判断，不按资源或对象名字特判；统计不会禁用背景对象或改写播放行为。扫描开销包含在 Observer 内，停止采样后不扫描；短暂只活在帧中途的对象可能不出现在边界清单。

粒子绘制坐标使用调用内 `DrawSpace` 快照：系统默认缩放、Local 非 Hierarchy 模式的位置/旋转，以及 Local Hierarchy/Custom 的完整变换矩阵，只在一次渲染器绘制内共用。粒子自身位置、总速度和事件局部坐标仍逐粒子读取；父变换、模块配置或相机变化会在下一次绘制重新建立快照，不跨帧保存场景引用。模拟、碰撞、曲线、随机数、顶点流布局和绘制顺序未由此优化改变。`Tools/Test-ParticleDrawSpace.ps1` 使用冻结旧 DLL 与当前 DLL 对照真实几何生成；覆盖范围与坐标内核基准限制见测试 README。实测收益仍需相同场景的新报告及关闭阶段探针后的对照。

schema 7 增加 `ParticlePool`：开始、结束及采样峰值页数，每帧上传页数峰值，托管缓冲保留容量与原生 CPU 缓冲有效长度；帧 JSON/CSV 另列当帧租借页数、空闲页数、顶点/索引容量。覆盖全部共享页和相机，不包含独立回退网格。托管字节不含对象/容器头，原生 CPU 字节不含分配器预留；两者都不是显存。读取不触发上传、分配或释放，只在采样回调和边界执行，其逐帧开销计入 Observer。开始/结束是独立快照，峰值仅覆盖实际采样帧。退出采样后最后一份数据保持不变，需重新采样才能观察后续回收。

验证突发负载时，保持特效列表、半径、倍率、镜头和 Bloom 状态一致，分别用 20、100、20 个固定实例各采样 30 秒（每次应用参数会重新预热并生成独立报告）。随后停止播放，在无测试实例时重新采样 10 秒，比较开始/结束与逐帧空闲页变化。128 是空闲尾槽回收阈值，不是总页数上限；未再使用的尾槽在空闲 120 个渲染帧后释放。背景效果仍可能使用池，不能要求全部页数必为零；也不要要求进程工作集立即回到原值。最后退出临时地图，检查红字、卡死及残留实例。离线测试覆盖清理路径，但退出后的采样器不会继续观察游戏。

画面对照单独进行：选择实际包含半透明、拖尾和折射的效果，检查交叠次序、裁剪边缘和闪烁；分别关闭/开启 Bloom，并打开实际内容提供的离屏预览窗口。对照优化前版本时保持相同参数。没有覆盖某类效果或预览入口时，记录为未验证，不以无红字替代画面验收。

“采样与报告”页默认勾选“记录 CPU 阶段、分配与合批原因”。它仅在常规采样期间启用源码中的数值探针，不安装 Harmony 补丁；停止、离开测试场后关闭。缓冲在计时开始前分配，最多保留 36000 帧，仅保存数值，不保留材质、贴图或测试实例引用。

报告区分进程分配、主线程分配、已覆盖阶段分配，并列出模拟、粒子排序与几何、拖尾、Sprite 材质准备、提交、网格填充、诊断捕获、合批追加/Flush、DrawMesh CPU 调用及 HDR/Bloom 快照构造。每阶段提供调用量、平均、P95/P99、最大单次耗时及几何规模。Inclusive 含子阶段；Self 只扣除本采样器已测的子阶段，不能把 Inclusive 相加。分位数按每帧累计值计算，包含零调用帧。阶段为零调用不代表渲染线程或 GPU 没有开销。

TXT 和 JSON 含阶段汇总与合批计数；另有 `.stages.csv`、`.batch.csv` 保存非零逐帧记录，以 `frame` 对齐 `.frames.csv`。帧 CSV 追加主线程分配和 Observer 的 CPU/分配列。Observer 仅覆盖统计回调本身；探针开销应通过取消勾选并重新采样检查，不能用 Observer 列代表全部诊断开销。关闭后的报告明确标记未采集，不输出虚假的零阶段记录。

合批原因分为接纳、独立路径拒绝和已有批次结束。`Accepted` 不代表实际减少批次；例如每次输入都接纳、随后因 `MaterialChanged` 结束，仍可能是 60→60。每次拒绝或结束只计首个命中原因；`MultiplePasses`、`UnknownShader`、`UnsafeShader` 区分 Shader 条件，`UI`、`CameraUI`、`Empty` 表示未尝试世界合批。诊断不改变透明绘制顺序。

阶段分配可能包含宿主 API 或内容脚本，不等于全部由 RimUnity 自身创建。未覆盖主线程分配用于寻找下一步插桩范围；进程总分配为近似全局计数，不能与主线程数值精确相减来推断其他线程。第一帧可能不完整。报告记录实际运行时版本、MVID、提供方、独立/内置来源与内置载荷哈希，不能仅凭磁盘上的 DLL 版本判断加载结果。

内置版对比步骤：保持独立前置未启用，关闭 DPA 和详细探针；固定相同特效、20 个实例、预热 10 秒、同一相机与分辨率。先开启 CPU 阶段采样 60 秒，再取消勾选采样 60 秒作对照；保持 144 FPS 限帧即可。若要比较 Bloom 开关，分别取得同条件报告，不从锁帧 FPS 推断 CPU 或 GPU 节省量。游戏内画面、真实消费者生命周期与 GPU 时间仍需单独验证。

schema 5 不再在采样期间刷新进程工作集与私有内存。旧的每秒 `Process.Refresh()` 与属性查询会阻塞主线程，已经在一次固定场景报告中观察到约 11ms 的 Observer 回调。现在仅在采样开始前、停止计时并退订事件后各查询一次，JSON 的 `ProcessMemory` 保存独立起止值和结束查询是否成功；帧数据中的工作集/私有内存列明确保留采样前快照，不能视为逐帧变化。托管堆仍按秒读取，分配和 GC 次数继续逐帧记录。停止后的内存查询及文件导出成本不进入报告。

CPU 阶段 schema 2 新增模拟调度、协调推进、事件派发及粒子属性求值阶段，共 22 个阶段。`ParticleAttributes` 按粒子调用，测量本身也有额外开销；比较时保留探针关闭的对照。增加子阶段后，`ParticleGeometry` 的 Self 定义随之缩小，不应直接与旧 schema 的 Self 比较。

报告新增四个互斥的主线程时间窗口及 `.windows.csv`：上一帧入队到 PrePoll、PrePoll 到桥接更新、桥接更新、桥接更新后到本帧入队。它们划分完整帧间隔，同时记录对应主线程分配；包含等待及其他订阅者，不等于 CPU 实际执行时间。这些窗口与源码阶段计时重叠，不能再次相加。第一帧、缺失或顺序不完整的边界不进入窗口汇总，也不记成零耗时。用于将未覆盖分配缩小到宿主更新前后，而不是直接归因给具体宿主子系统。

“清空特效并采样空场景”会先停止当前采样、清理测试实例，再开始无粒子的基线采样，报告标记 `EmptyBaseline=true`。镜头、分辨率和面板折叠状态保持一致；与有负载报告对比时，检查每帧系统/粒子数量及提交项，不能假定二者差值全来自粒子函数。之后可在播放控制页重新应用参数恢复固定负载。

schema 6 的兼容世界粒子使用有界共享网格页：不同材质/图层仍保留独立子网格段和原来的提交顺序，每段保留自己的边界；相邻同材质仍可合并。整页构建完成后才提交，不兼容项会先提交已有页，然后走原独立路径。每页最多 65536 顶点、196608 索引和 256 个材质段；同帧不同相机/页不复用已提交网格。异常退出丢弃未提交页并清空材质引用。Shader 适用性、折射、多 Pass、属性块和存储绑定规则保持不变。

报告新增 `ParticleUploadPages` / CSV `particle_upload_pages`，配置标记 `ParticleUploadMode=OrderedSubmeshPages`。这是经过框架共享页路径的网格数，不含独立回退，也不是宿主或驱动实测上传次数；提交段数可以仍是 60，而共享页只有 1。`BatchFlush` 现在包含整页所有绘制段的 CPU 提交，耗时可能从 Renderer 内转移到相机绘制末尾，因此与旧版比较应看 Bridge/Scene 整体以及宿主后续窗口，不直接比较 Renderer 自身耗时。GPU 上传执行时间仍未测量。

“开启详细耗时探针（60 秒）”复用下文的卡顿诊断，生成独立的 `particle-spike-` 报告，用于区分加载、生命周期、预热、模拟、网格和上传耗时。离开测试场会停止由测试场启动的探针。常规采样会标记详细探针开启的帧，避免把探针自身的开销误认为性能退化。

播放器每帧最多创建 16 个实例，并在已耗时 8ms 后暂停本帧继续创建；单次实例化不可中断。固定模式在填满并预热前不开始采样，报告的 `PlaybackMode=FixedInstances`、`ParticleSeedsFixed` 和 `WarmupSeconds` 标明条件；采样期新建实例应为 0。创建/销毁模式不追赶积欠发射，报告记录实际创建速率与限流帧；并发上限和实例寿命也会限制实际密度，请求频率不能直接当作实际频率。

比较稳定运行成本时，固定同一组选项、实例数、相机位置与缩放、分辨率、Bloom 设置及采样时长，折叠面板后等待采样完成。关闭 DPA 详细模式和其他详细探针，先比较常规报告的帧间隔 P50/P95/P99；另开一轮详细探针定位热点。固定实例数不代表粒子数逐帧恒定，原有脚本、动画及变动的真实帧间隔仍会影响播放，不承诺位级确定性。

帧间隔、托管分配和内存包含整个游戏、其他模组与采样本身的开销；粒子数量只统计测试实例。地图提交项不是驱动实际 DrawCall，未测量 GPU 执行时间或显存。第一条间隔可能不足整帧。测试场复用进程资源缓存，不保证每轮都是冷加载；已经加载的其他模组及真实时间脚本也可能影响结果。场地中的预制体仍执行自己的脚本，测试结果应结合所选内容判断。

测试场未启用时不注册播放和采样回调，也不安装测试场计数补丁。既有“卡顿诊断”手动采集入口保持独立，只有用户显式开启时才运行。

### 绘制合批与报告

完整特效实例的创建、复位与回收由上层模组作者管理。RimUnity 不提供预制体实例池。测试场的创建/销毁模式持续走正常 Instantiate/Destroy 路径；固定模式只在建立或重启场景时实例化，清理时销毁，稳态采样不包含这部分成本。

世界粒子提交按原顺序合并相邻的兼容段，可跨粒子系统和预制体实例。必须使用同一材质对象、同一图层、单个 Shader Pass、无实例参数覆盖，而且程序已在资源加载时完成合批兼容检查。每批最多 65536 顶点、196608 索引；遇到不兼容项或容量边界立即提交。带多 Pass、存储缓冲、场景抓取、原生顶点/实例/图元编号或未检查程序的绘制保持独立。不会跨越不同材质去重排透明物体，交错材质的合批收益可能较小。

合批直接追加已有世界坐标和顶点流，不合并或延长 GameObject 生命周期，也不改写模拟时间。每个相机及连续段使用独立动态网格，同帧提交后不再次覆盖；峰值后的闲置尾槽会回收，读档和退出图形设备时全部释放。保留已有逐粒子排序、UV、颜色和自定义顶点流。UI 粒子以及显式的粒子材质诊断快照使用独立提交。

常规报告 schema 3 新增 `ParticleDrawsBeforeBatch` / `ParticleDrawsAfterBatch`，TXT 汇总前后数量及减少比例，CSV 对应 `particle_draws_before_batch` / `particle_draws_after_batch`。这些值统计本帧经过世界粒子绘制入口的所有相机，包含不兼容项的独立 Pass；不包含普通 MeshRenderer、UI 或 HDR/Bloom 再绘制，也不是驱动实测 DrawCall。仅在常规采样开启时累计。详细探针的 `Particle.BatchFlush` 标记合并网格提交，原有单 Renderer 绘制计时不再包含延后的整批上传。

对比旧报告时保持特效集合、并发、频率、寿命、视角与 Bloom 相同，关闭详细探针，使用相同采样时长。先播放至少一轮最长寿命，再单独开始常规采样，可以比较稳定阶段；从“应用参数并播放”开始则包含首次创建成本。合批数量下降不等于帧率按同比例上升，粒子模拟、像素覆盖和其他模组仍占用时间。

粒子固定顶点布局按顶点连续写入上传缓冲；HDR 派生绑定按源材质版本、参数版本与管线状态缓存，参数变化时生成新绑定，保留在途快照的旧状态。动画访问器按类型与属性路径共享，不保留场景对象；首次遇到属性仍需编译。每个粒子系统的空闲拖尾缓存限制为 32 个容器、合计 1024 个采样点容量；HDR 标记集合最多保留 8 份、单份容量不超过 16384，归还时清空绘制引用。

普通网格预制体和蒙皮网格仍按各自的 MeshRenderer 提交；本轮跨实例合批覆盖的是预制体中的粒子绘制，没有把 Shader 的 `enableInstancing` 标记当成已接通 GPU 实例化，也没有改变模拟精度或转为 GPU/Burst 模拟。

## 复现一次并导出

1. 如果要测冷启动，先重启游戏。已经加载过的资源不会因开始采集而变冷；工具不会清空游戏的 Shader/纹理缓存。
2. 关闭其他持续采样的诊断窗口，进入准备触发特效的场景。
3. 点击 **卡顿诊断 1 · 开始采集（60秒）**。复杂复现场景可用 120 秒入口。
4. 关闭开发菜单，空等两三秒取得空闲基线。
5. 触发特效一次；等它稳定后，再触发同一特效一次。尽量保持相同视角、位置和游戏速度。
6. 点击 **卡顿诊断 3 · 停止并导出**。不手动停止也会到时自动保存。

可选用 **卡顿诊断 2 · 添加触发标记** 区分几次操作。标记写入后再关闭菜单并触发特效；菜单本身会影响帧间隔。

完成后会在游戏配置目录的 `RimUnityReports` 子目录生成四个同名前缀的文件，并复制文本报告路径到剪贴板：

- `.txt`：可直接阅读。含测量边界、最慢帧、重叠事件、首次与后续调用、探针覆盖和前后资源状态。
- `.json`：完整的已保留事件、全部聚合统计、帧样本、上下文与探针覆盖。
- `.events.csv`：可按时间、线程、资源或父调用 ID 筛选的事件。
- `.frames.csv`：所有已保留的主循环帧间隔、分配增量、GC 次数和粒子数量。

“再次导出上次报告”用于重新保存内存中的最后一份采集，包括导出失败后的重试；开始新采集会替换它。关闭开发者模式、切换游戏会话或关闭图形设备也会结束采集。报告不会写入存档。

- 自定义 Shader 加载、标准粒子变体、Linear/HDR 变体、宿主编译和编译缓存标记、磁盘 Shader 缓存读取、Shader Module 获取。
- 纹理加载、缓存读取/图片解码、首次驻留、像素上传、设备纹理分配、上传提交、纹理驻留腾挪。
- 脚本生命周期队列、回调、首次绑定生命周期委托、脚本异常。
- 粒子播放、重置、整组模拟、预热、物理扫描、粒子和拖尾绘制、网格提交、宿主网格上传。
- 宿主图形管线获取、主线程整帧事件、渲染线程整帧事件，以及桥接 Bloom/HDR 阶段。

## 怎么读报告

先看“采集完整性”和“探针覆盖”，再看“最慢帧间隔及重叠事件”。`OK` 表示探针安装成功，不代表目标调用一定经过该入口。

`Asset.Get` 的 `cache=miss` 表示资源模板缓存未命中；`cache=hit` 表示资源对象已经存在。`Shader.Compile` 的 `compilerCacheHit=True` 是宿主返回的缓存标记；False 也可能来自宿主覆盖文件分支，需结合 `Shader.CompileMiss` 是否出现判断是否实际编译。`Texture.ReadDecode` 的 `textureCacheHit` 是宿主纹理缓存标记。`Texture.FileResident` 会记录调用前是否已有设备资源和 CPU 像素。

`Prefab.Build | instance` 是实例对象图构建，Awake/OnEnable 还可能在外层实例化事务结束后发生，单列为 `Lifecycle.Drain/Callback`。按时间线一起检查，不能把对象图构建时间当作整个 Instantiate 的时间。

粒子组事件会记录待预热根数量、模拟时间跨度及粒子数，实例事件会记录容量、上限、duration、speed、碰撞、拖尾等配置。组内计数扫描最多 512 个系统；上下文最多列出 256 个活动系统。

`First/Second/Third` 始终是**本次采集最早观察到的调用**，不自动等于进程冷启动。`duration` 是包含子调用的 CPU 墙钟时间，`self` 扣除同线程、同会话内已测量子调用。嵌套 duration 不能相加，跨线程的耗时也不能相加当作帧时长。宿主帧事件是独立的外层时间段，不参与嵌套扣除；停止时的 partial main frame 只是部分帧。

所有 `GPU.*`、渲染帧和 Bloom/HDR 计时都是 **CPU 端调用耗时**。工具没有插入 GPU timestamp、像素读回或设备空闲等待，不能用它直接声称 GPU 执行耗时或精确呈现延迟。帧号是最近观察到的主线程桥接帧号；关联渲染线程时优先使用相对毫秒时间。

## 开销与限制

动态探针只在显式采集期间安装，停止时移除；自有 JSON 和渲染阶段的直接探针在未采集时只检查一个空会话引用，不分配对象。安装探针和读取上下文不计入采集时间，但安装过程与 JIT 仍可能影响冷启动条件。采集期间的反射、参数装箱、字符串、锁和记录分配会增加开销，因此本工具用于定位明显 spike，不用于证明微秒级性能改善。

每个 `stage + detail` 聚合全部已完成调用；事件保留最早三次、至少 2ms 的慢调用和异常。最多 4096 个聚合组、25000 条事件、12000 个帧样本。达到上限会显式报告丢弃数量；普通未保留调用仍进入聚合统计。父事件可能没有被保留。停止时还在运行的调用不补算为完整调用，报告列出未完成数量。

采集期间不写磁盘，停止后才导出。采集不会生成特效、清理资源缓存、强制 GC 或修改渲染设置。记录只持有文本和数值，不保留 Map、Pawn、组件或设备资源。用户目录会被替换为 `<USER>`；报告不收集存档内容、Shader 源码或贴图像素。

## 定向验证

`Tools/SpikeCaptureTests` 覆盖嵌套计时、异常、跨线程聚合、截断、会话隔离、快照隔离；可额外指定运行时程序集、游戏目录和 Harmony 路径，验证实际探针安装/移除、实际资源缓存入口和异常透传、out 参数缓存标记及导出结构。

首次使用仍应在游戏内按上述步骤触发两次特效，确认采集到目标资源及实际卡顿。离线测试不代替真实图形设备下的复现。


### DPA 根 CPU 汇总与 HDR 阶段（Detail v4）

剪切板报告的 `ROOT CPU SUMMARY` 只累加最外层已覆盖入口，嵌套调用不会重复相加。
会话均值、最大值和分配量使用完整有效的观测帧，排除重置后的首帧、栈异常帧与当前未结束帧。
P50/P95/P99 只使用最近最多 8192 个有效观测帧；报告同时给出这段样本的宿主帧号范围。
没有探针调用的宿主帧属于未观测帧，不当作零耗时。轻量、详细模式覆盖范围不同，不能把不同模式的根耗时差全部当作探针成本。
这些仍是含探针开销的主线程入口耗时，不是完整模组、所有线程或 GPU 时间。

详细模式增加 `HDR SNAPSHOT STAGES`，HDR 与 Bloom 各自记录 Setup、FilterDynamic、SortDynamic、MergeAndLookup、BindingRefresh、CommandCopy。
每份快照先在局部累加，完成或异常退出时合并数字计数；关闭详细采集后不读取这些阶段的时钟或分配计数。
工作量包括动态/持久输入项、成功复制命令、唯一源绑定刷新次数，以及每条命令所复制 Uniform 结构的逻辑内联字节。
该字节数排除其他命令字段、纹理/存储内容和引用数组，不是分配量、总复制量或实测内存带宽。
阶段计时本身及嵌套 Harmony 探针会增加开销，应与轻量模式和 Cleanup 后帧时间交叉核对。
最慢粒子提交统一使用 `UnityEngine.Time.frameCount`，并在重置时与会话记录一起清空；暂停时保留记录用于导出。
报告额外导出实际加载的 RuntimeInfo 版本、Provider、PayloadHash 和各程序集 MVID，程序集文件版本不能替代载荷身份。

同场景预热后，轻量与详细模式各重置并采样至少 60 秒，再导出当前报告。
最后 Cleanup 探针，记录同场景的整体帧时间作为探针影响参考；这段整体帧时间不能单独归因给 RimUnity。


### 一键混合粒子压力场景

开启开发者模式与上帝模式，从调试菜单进入 `RimUnity / 特效性能测试场`，在播放控制页点击
`一键建立 / 重建混合粒子压力场景`。无需勾选导入资源，也允许当前没有可测试的导入 prefab。
按钮只在开发权限开启时显示，实际操作会再次检查权限；关闭上帝模式后，混合负载在下一次测试场更新清空。

`mixed-particles-v1` 固定为 12 组，每组 4 个根实例，共 48 个根实例。
覆盖普通/拉伸/水平/垂直面片、网格粒子、粒子拖尾、多层噪声、寿命曲线、图集动画、复杂顶点流、自定义空间及 Birth 子发射器。
使用内置透明和加法粒子材质、独立图集与网格，避免导入 prefab 的脚本或导出变化干扰对比；不修改资源模板。
每个系统最多 64 粒子，父子发射器组的父系统上限 16，子系统保留事件驱动且不独立循环。
图集和复杂顶点流覆盖 CPU 数据生成路径，不能替代任意自定义 Shader 的 GPU 正确性测试。
这组场景不覆盖 UI 粒子、碰撞/触发器、外部力场、折射或所有真实资源组合，后者应另外定向测试。

重建固定种子、出生参数、根位置与朝向，把相机跳回地图中心并将缩放设为 24；进入前的缩放会在退出测试场恢复。
实例按既有每帧 16 个/8ms 预算建立，填满后预热 12 秒，随后自动采样 60 秒，采样结束仍继续循环播放。
稳定指配置、根数量和粒子上限可重复，不承诺不同帧间隔下逐帧粒子数或图像位级一致。
报告记录 Scenario、实际参与的组、每组根数量、粒子上限、种子以及采样开始的实际 CameraRootSize。
Bloom 与 CPU 阶段采样开关沿用当前设置，比较两次报告时必须核对；采样期间保持相机与窗口状态一致。
同一按钮可重建，`停止播放并清空实例` 会清理全部测试根与自有材质/网格/图集；退出仍沿用临时地图清理与禁止保存规则。
此场景只在显式打开测试场并点击后创建，不给正常游戏新增逐帧扫描或生成任务。


### 混合场景 v2：世界材质与实际 Bloom 覆盖

`mixed-particles-v2` 保留 v1 的十二组配置、48 个根实例、种子与位置，但改用明确不含 UI 遮罩能力的
`RimUnity_WorldParticleAlpha` / `RimUnity_WorldParticleAdditive`。这两个材质沿用粒子颜色、UV、透明/加法混合语义，
片元阶段不声明 UI 遮罩或存储缓冲，因此经过原有安全检查后可参与世界合批。
旧粒子与 UI Shader 不变；存储缓冲、抓屏或编号相关程序仍须遵守原有合批拒绝规则。

全部测试系统及子发射器使用 Layer 30。混合场景的 Bloom 开关只覆盖本测试地图的瞬时 BloomFrame，
启用时掩码为 `1 << 30`，阈值 0.8、强度 0.6、SoftKnee 0.5、Scatter 0.65；关闭时禁用测试地图的 Bloom。
不改写保存设置，不调用 SetLayerEnabled/ReleaseLayer，不接管其他内容模组的层。正常地图、停止混合场景或退出后沿用原设置。
切换开关会结束并导出当前采样，防止一份报告混入两种条件；随后重建或手动开始常规采样。

报告记录 BloomSource、实际掩码和参数、StressWorldLayer，并在 CPU 采样开启时记录每帧 HDR/Bloom 快照调用数与绘制项数。
TXT/JSON 汇总包含 Bloom 非空帧数，新增 `.snapshots.csv` 保存逐帧数据。CPU 采样关闭时这部分不可用，不能解释为零捕获。
非空快照只证明准备了 CPU 绘制命令，不能当成 GPU 已完成绘制或画面已发光的证明。
v1 的 UnsafeShader 独立提交与空 Bloom 报告仍可保留作旧路径记录；v2 改变了覆盖，不应直接宣称二者总耗时差全部是优化收益。


### 混合场景类型耗时与拖尾端点复用（CPU 阶段 schema 4）

场景仍为 `mixed-particles-v2`，配方、种子和透明提交顺序不变。采样前把初始系统及其子发射器按显式配方编号登记为数值身份；采样结束清空身份映射，不保留场景对象。新增 `SimulationSystemStep` 测量各系统的推进调用，作为 `SimulationAdvance` 的子阶段。不要把这两项 Inclusive 相加。

TXT 和 JSON 增加 12 类测试配方的 Renderer、Geometry、Attributes、Sort、TrailGeometry 和 SimulationSystemStep 汇总；另写出 `.families.csv`。均值按全部已记录帧计算，尾部未提交帧不进入类型汇总。这些数据与全局阶段重叠，没有类型分位数，也不把延迟 Flush、HDR、Bloom 或 GPU 工作归给某个配方。没有登记的系统仍进入全局阶段统计，不能把类型之和当作框架全部成本。

类型归属只在 CPU 详细采样时启用。探针增加计时和汇总操作；测量收益时另做关闭 CPU 阶段采样的对照。常规玩家运行不建立身份映射或采样缓冲。

拖尾几何生成现在在一次绘制内复用相邻段共有端点的宽度和颜色曲线结果，每个端点只求值一次。位置、段朝向、顶点顺序和 UV 规则不变；不跨调用缓存，因此编辑曲线、改变寿命、Ribbon 点属性和下一次相机绘制会重新求值。离线旧 DLL 对照覆盖 1620 种组合、9 个输出通道；真实画面和整帧收益仍以游戏内复测为准。


### Curl 噪声的局部数学复用

`ParticleNoise.Curl` 的 Medium/High 势场共用同一个采样位置，现在在调用内共享格点、位移、插值权重、导数和格点哈希盐。High 只累积 Curl 实际使用的每组两个导数分量；Low 仍使用原来的一组势场计算。固定的 12 个梯度改为私有数值表，按值返回；不建立跨粒子、跨帧或地图缓存，不更改随机序列、噪声质量、层数、采样频率或模块参数。

定向测试 `--noise-reuse <优化前RimUnity.dll>` 对照旧 DLL，覆盖三种质量、多种种子、格点边界、负数/极端坐标和六层累积，逐位比较输出。另外运行 72 种连续粒子模拟组合，比较全部粒子字段，并显式验证尺寸噪声求值。单独的 Curl 基准预热后零分配。完整显式 `Simulate` API 基准仍含该 API 原有集合分配，不应将其归因于 Curl 或等同于每帧协调推进路径。

离线微基准只说明目标代码的收益；整帧收益继续使用相同 `mixed-particles-v2` 场景、Bloom 关闭、相同 CPU 阶段开关的报告验证。该变化没有增加探针或改变 CPU 阶段 schema 4。


### 排序坐标与面片速度复用

空间排序先用本次 DrawSpace 为每个粒子计算世界坐标，再执行原来的比较公式：Depth 仍对两个坐标的差做点积，Distance 仍比较相对相机距离的平方；不转换为标量深度键，不增加相等键的次级排序。年龄排序直接读取年龄字段，避免复制整份粒子。坐标缓冲归 Renderer 所有，只保留数值容量；每次相机绘制重新填充，成功或异常后都清空并释放当前系统引用。

面片和 Mesh 的速度朝向，以及 Stretch，复用属性阶段用 DrawSpace 得到的世界速度；可见性检查按需要单独计算一次。朝向辅助方法不再接收未使用的完整粒子值。没有跨调用缓存，不改变透明系统间提交顺序、材质或模拟。

`--sort-reuse <优化前RimUnity.dll>` 旧 DLL 对照覆盖 675 种几何/可见性组合、9 个网格通道，以及 810 种排序配置、每种三次连续绘制，包括坐标空间、缩放、相等/近相等键、事件空间、相机和变换变化。另验证异常准备后清理及恢复；预热后排序和几何基准均检查零分配。CPU 阶段 schema 仍为 4；局部离线收益不代表整帧收益，继续用相同混合场景复测。


### 只读粒子参数与四角点批量写入

几何生成、DrawSpace 坐标求值和面片轴计算使用内部只读粒子参数，减少大粒子值的传递复制；不改变公开粒子 API 或模拟数据。常见 Default / UV-only / Zero 布局按四个角点为一组写入数值通道，保持原位置运算、顶点/索引顺序、颜色、法线、切线及 UV。Default 保留自定义通道，显式 UV-only/Zero 仍将对应通道置零。General 布局继续走原来的逐顶点求值路径，Mesh 与拖尾写入规则不变。

批量写入先保证列表容量、扩展数值元素计数，再立即填满四个槽位。Span 只在同步写入期间使用，不保存到字段，也不跨同一列表的扩容或回调；只处理 unmanaged 数值类型。没有跨帧缓存、全局注册表、资源身份判断或新探针，CPU 阶段 schema 仍为 4。

`--geometry-batch <优化前RimUnity.dll>` 组合运行几何、可见性、排序、全部数值流及非零自定义数据对照，另覆盖 0–1024 粒子的连续缓冲增长、ClearMesh 和布局切换。检查所有九个网格通道和末端 VertexID，预热后验证零分配；内部只读签名与测试人口归属夹具同步适配。局部微基准收益仍需同场景游戏报告确认。


DPA 兼容核验：排序坐标准备仍可拆分为辅助函数，但 `List<int>.Sort` 调用保留在 Renderer 的 `Draw` 内，供现有定点插桩定位。准备与排序共同处于同一个 CPU 阶段和 `try/finally` 中；失败也清理部分坐标和系统引用。真实 DLL 元数据检查应分别在 HDR 构造和 Draw 中发现一个排序调用点，并成功编译 Submit/TryAppend/Flush 探针。

### 合批页的索引与包围盒遍历

`Mesh.AppendParticleGeometry` 保留八个通道的批量复制及网格独立所有权；索引仍在任何网格修改前完成合法性检查。索引验证、追加时的偏移写入和包围盒扫描改用同步 Span，索引目标先保留容量，再立即填满新增范围。成功追加顶点后，合法索引加偏移不会超出顶点总数；加法仍保留 checked。包围盒保持原先包含首顶点的 Min/Max 运算顺序，不改变透明绘制范围或合批条件。Span 不跨扩容、回调、帧或线程保存。

`Tools/ParticleUploadTests` 新增 `--append-only`：加载真实 Core DLL，检查通道、索引偏移、子网格包围盒、清空复用、非法输入拒绝及源缓冲独立性，并输出逐字节结果摘要。通过 `RIMUNITY_RUNTIME_DIR` 指定旧版或新版目录，在独立进程中比较摘要；不加载 GPU。基准使用 56 次输入、48 个连续范围，覆盖 800/3000/5400 个四边形，预热后检查零分配。比较时两侧应采用相同编译设置；可设置 `DOTNET_TieredCompilation=0` 避免测试中途分层编译干扰。无参数的原有测试继续验证真实宿主顶点/索引打包及提交范围。离线追加耗时不包含上传或 GPU 执行时间，整帧收益须使用相同混合场景复测。

### 拖尾绘制中的坐标变换复用

每次 `DrawTrails` 建立一份只含数值的 `DrawSpace`，普通局部/自定义空间采样点共用当前系统变换，减少逐点读取同一变换的工作。世界空间与 Ribbon 点仍直接使用已有世界坐标；事件局部点仍使用所属 EventSpace 的位置、旋转和缩放。快照只在同步绘制调用内有效，下次相机绘制或系统变换变化后重新建立；不增加字段缓存、资源身份分支、探针或持久状态。顶点写入、透明顺序、曲线求值与距离/UV 规则不变。

`--trail-reuse <优化前RimUnity.dll>` 保留 1620 组空间、缩放、纹理模式、Ribbon 与曲线对照，新增全部支持顶点流、0–257 采样点缓冲增长、非空追加、清空复用、相机方向和父级/自定义变换变化的三次连续绘制对照。测试夹具兼容旧四参数和新五参数 AppendTrail；八种坐标路径的基准包含每次绘制的快照建立，并检查预热后零分配。共享 WorldPosition 辅助函数另由普通粒子几何与排序旧 DLL 对照覆盖。基准只测 CPU 几何，游戏内仍使用原混合场景、Bloom 关闭与相同 CPU 采样开关验证。

### 网格粒子的重复方向变换

已解码的 MeshGeometry 同时记录有效顶点范围内的法线/切线 xyz 是否逐位相同。该元数据与原网格解码快照共用所有者和失效路径，不新增全局缓存；切线 w 不参与方向比较，仍逐顶点复制以保留 handedness。负零和 NaN 按位区分，不用近似向量相等或资源名判断。

每个粒子只对重复方向变换并归一化一次，结果不跨粒子或姿态保存。不同方向、缺失或短于顶点数的通道仍遵守原回退规则；空网格或没有法线时跳过未使用的逆转置矩阵。需要法线时保留原矩阵求逆、奇异矩阵和归一化规则，不改顶点、UV、索引或透明顺序，也不改变已解码网格的既有刷新契约。没有新增公开 API、存档字段或探针。

`--mesh-directions <优化前RimUnity.dll>` 对照真实旧 DLL，覆盖 350 组输入、每组三次绘制，逐字节比较九个网格通道；包含 0–129 顶点、缺失/部分/重复/不同方向、切线符号、负零与 NaN、负/零缩放、动画、事件空间、网格重设与变换变化。另验证多个已缓存网格交替选择，检查方向元数据随当前网格刷新。预热后的 CPU 几何基准覆盖 4/32/128 顶点及五种通道模式，包含属性和绘制准备但不含上传/GPU；两侧采用相同编译设置并交替运行，检查零分配。整体收益继续以同条件混合场景报告为准。

### 小幅优化的游戏内 A/B 对照

将优化前后的已验证内置载荷及配套引用文件固化到同一个离线 A/B 包，以 SHA256 固定版本，不重新构建。包内 `bundle.json` 记录两版 MVID、载荷哈希及每个文件的目标/源路径和哈希。`Tools/Switch-PerformanceAB.ps1 -Bundle <包目录> -Variant Inspect` 只核验；`-Variant A` / `-Variant B` 在游戏退出后切换。脚本先检查全部源和目标，拒绝不属于两版的现有文件，全部备份后才覆盖，并逐文件复核哈希；`last-switch.json` 记录本次选择。若切换中断，应保持游戏关闭并重跑所选版本的切换，直到全部核验成功。

每版重启一次游戏，使用同一存档和混合场景，Bloom 关闭、CPU 阶段开启、DPA 关闭，保持相同限帧、分辨率与相机。每轮重新点击混合压力场景，等待自动预热 12 秒、采样满 60 秒；每版三轮，保留全部报告，不挑最好一轮。三轮之间不打开其他预览、不改设置，不手动提前开始采样。先核对实际加载 MVID、配方、背景数量、提交数量和几何工作量，再比较各轮目标阶段及覆盖总 CPU 的范围与中位数。分位数应比较每份报告的值，不能把三个 P95 取平均当作合并 P95；单个极值也不能证明稳定性改善。若差异落在重复采样波动内，结论为尚未确认，不继续靠微小改写追逐噪声。完整游戏 CPU、渲染线程和 GPU 仍不在这些阶段的覆盖范围内。

### 已准备顶点流的直接打包

粒子模板完整初始化全部 12 个数值槽后，每个顶点复制该模板并直接填写布局中的 UV、UV2、UV3、UV4 和 VertexID，不再经过通用 StreamValue 和逐分量 Vector4 索引循环。模板复制覆盖全部槽位，因此只在未准备的回退路径清零；拖尾及 ClearMesh 后的手工顶点继续走原来的通用求值。下一帧 UV 映射集中在同一个辅助函数，准备和回退两条路径保留相同浮点运算顺序。

流布局仍由原 setter 校验和构建；重复流、偏移、12 分量上限、自定义值和 VertexID 不变。不改变图集帧选择、随机序列、材质/纹理、绘制排序或 GPU 布局，不增加缓存和探针。`--stream-pack <优化前RimUnity.dll>` 覆盖 450 组布局/渲染模式/相机配置，每组三次连续绘制，准备与清空后的回退输出均逐字节比较九个通道；另覆盖 UV2 的零/负/极小尺寸、负零和非有限值。八组完整几何基准包含动画、属性与绘制准备，检查预热后零分配，不包含上传或 GPU。离线收益须由相同场景的三轮游戏报告确认。

### 关闭属性模块时的求值路径

尺寸生命周期、速度与噪声模块都关闭时，SizeAt 直接返回出生尺寸，省去无用的寿命比例和固定种子随机混合因子。两种颜色模块都关闭时，ColorAt 直接转换出生 Color32，省去两次乘白色；转换结果为有限颜色分量，保持原输出。任一相关模块开启后沿用原公式、顺序与随机盐。Age、SizeAt、ColorAt、CustomAt 的内部粒子参数使用只读引用；公开粒子 API、模拟写入、CustomData 覆盖优先级和存档身份不变。不缓存属性结果，不按资源身份选择路径，不增加探针。

`--attribute-evaluation <优化前RimUnity.dll>` 对照 64 种模块开关组合、四种曲线/渐变模式、十组寿命与尺寸边界，逐字节检查 2560 组属性结果，包括自定义覆盖优先于关闭模块的情况。另运行 72 组连续模拟并比较全部粒子字段，以及完整顶点流/几何回归。十组预热 CPU 几何基准覆盖模块关闭、尺寸、颜色、自定义数据和全部开启，检查零分配；不包含上传或 GPU，游戏内收益以同条件三轮报告为准。

### 简单 Billboard 的连续顶点缓冲

普通场景中的简单 Billboard（默认、UV-only 或无数值流布局）将位置、法线、切线、颜色和三组 UV 直接写成最终上传顺序的 92 字节记录。渲染器只持有本次生成的数值工作区；提交同步复制到共享网格独占的缓冲，上传时整块复制到原生 CPU 存储，不再经过七个通道列表和逐顶点重新交错打包。索引、透明排序、图集动画、浮点计算顺序和 GPU 布局保持不变。仍保留渲染器到共享网格的一次复制，并未直接借用渲染器列表，也未实现 GPU 实例化。

UI、相机 UI、跨 Sprite 纹理段、复杂数值流及可视诊断捕获保持原生成路径；独立提交可以使用连续缓冲。共享页内允许两种来源混合：连续缓冲起始的页继续按最终布局追加其他几何，普通通道起始的页将后续连续记录展开到原通道，避免中途重建整页。公共 Mesh 通道读取或修改按需恢复普通通道，Clear 清空两种表示，镜像和三角边展开保持原规则。容量及内存诊断计入连续缓冲，不新增全局缓存、存档字段、资源身份特判或采集探针。

`ParticleDrawSpaceTests --packed-billboards <优化前RimUnity.dll>` 覆盖 1620 组空间、缩放、渲染模式、对齐、布局、相机配置，每组两次绘制逐字节对照，并检查旧通道没有重复写入；另测试 UI/诊断/复杂布局回退及重置。生成、共享页追加和原生 CPU 打包基准覆盖 1/64/2944/8192 粒子、1/56 个输入批次，检查预热后零分配。该基准中的旧运行时使用当前 Core 的普通通道路径，不包含 GPU 或完整游戏时间。

`ParticleUploadTests --packed-only` 验证最终原生字节、混合追加顺序、子网格边界、非有限值、读取修改后再追加、无别名持有、镜像与边展开及失败输入不改变网格；`--packed-host` 通过真实宿主对连续/混合页进行上传及子网格解析。安装后的收益与最终画面仍需同场景游戏内报告确认，先采样一轮，差异较小或不稳定时再追加。

### 面片朝向与屏幕投影计算

相机快照在当前绘制内同时保存 View 的两个方向和 VerticalBillboard 的横轴；它们随每次相机快照重建，不跨帧或跨相机缓存。水平、垂直面片不先计算随后丢弃的朝向；非零速度的 Stretch 直接使用速度方向。出生方向与三维旋转覆盖二维轴时，不再计算被覆盖的二维三角函数。Stretch 的长度缩放仍在覆盖分支之前执行，保持出生方向粒子的原有拉伸尺寸。

场景尺寸限制仍投影原来的四个端点，保留透视除法、近零 w、视口和整数屏幕尺寸的运算顺序。投影直接求 x/y/w，省去未使用的 z 和通用矩阵传值；没有采用正交近似、中心消去或新的取倒数方式。Overlay 继续使用已有 UguiProjection。此轮不增加运行时探针、公共 API、全局缓存、存档字段或资源身份特判。

`ParticleDrawSpaceTests --billboard-phases` 单独测量 Clamp、包含 Clamp 的轴生成和连续四角写入，避免相加重叠阶段。`--billboard-math <优化前RimUnity.dll>` 逐字节比较 5232 组投影、2160 组尺寸边界及 2160 组朝向结果，覆盖任意投影矩阵、近零 w、视口截断、负零、NaN、无相机/透视/正交、出生方向与三维旋转及速度；另交替测量完整几何生成，包含属性与每次绘制的相机准备，检查预热后零分配。完整顶点输出继续由 packed-billboards 和 stream-pack 对照；不把离线阶段比例解释为游戏整体收益。

### 拖尾线段的四顶点写入

拖尾的默认、仅 UV 和无数值流布局按线段一次预留四个顶点槽位，分别填写原有的九个几何通道，省去每个顶点重复追加和流布局判断。两个端点分别转换一次 Color32，保持四角颜色、UV、法线、切线和索引顺序。复杂流继续通过原 Vertex/PackStreams 求值；不复用历史粒子属性，不改变曲线、空间变换、宽度、拖尾采样或图像质量，也不增加缓存、探针或资源身份特判。

`ParticleDrawSpaceTests --trail-reuse <优化前RimUnity.dll>` 覆盖 1620 组空间/纹理模式/点数/曲线对照，以及 3430 组布局与容量变化，每组三次连续绘制；后者逐字节比较九个通道，包含普通拖尾和 Ribbon、所有已支持流、清空和追加、相机方向变化及退化方向。CPU 基准覆盖四类布局、八组空间配置，交替测量并检查预热后零分配。该基准只包含几何生成，不含提交、上传和 GPU；整体收益以同条件游戏报告为准。

### 混合页的通道交错写入与包围盒

普通顶点通道追加到已有连续粒子页时，在交错写入 92 字节顶点记录的同一次遍历中计算这批顶点的包围盒，省去随后对位置通道的重复扫描。写入辅助函数只接收已校验长度的通道；Span 不跨源列表扩容，也不保存到下一帧。包围盒保留原来的首点初始化和逐点 Min/Max 顺序，包括负零与非有限输入。原生上传布局、子网格顺序、页所有权和索引偏移不变；索引仍在修改网格前完整校验。

`ParticleUploadTests --packed-snapshot <摘要文件>` 可在设置 `RIMUNITY_RUNTIME_DIR` 后分别运行旧/新 Core；同一个测试程序对 576 份原生顶点、索引及整体/子网格包围盒快照生成摘要，覆盖空/大输入、各种混合顺序、负零、非有限值、读取物化及清空复用。配合 `--packed-only` 和 `--packed-host` 验证异常输入、独占缓冲与真实上传消费者。`--packed-batch-bench` 先充分预热，再比较连续/交替混合/首批连续后续普通三种输入序列；性能对照须在同一工具下交替运行优化前后的 Core，不能把程序内 packed 与普通页的比较当作本轮优化前后对照。CPU 基准包含追加与原生打包，不包含游戏整体和 GPU 执行时间。

### 简单网格粒子的连续通道写入

Mesh 粒子的默认、仅 UV 和无数值流布局按当前源网格顶点数一次预留通道槽位，连续填写位置、UV、法线和切线；颜色和自定义通道按该粒子的值批量填充。复杂数值流继续使用原 Vertex/PackStreams。变换矩阵、方向归一化、缺失通道回退、切线符号、图集 UV 和索引顺序保持不变；各流的最终状态也保持一致。所有 Span 都是渲染器已有数值工作区的同步切片，不跨源/目标扩容或提交，不新增跨帧缓存或探针。

网格绘制归入 Renderer.Meshes 文件，主粒子绘制入口仅派发到该路径，避免扩大公共热函数。`--mesh-directions <优化前RimUnity.dll>` 对照 350 组配置，每组三次绘制，逐字节比较九通道，并检查已缓存网格交替选择。CPU 几何基准覆盖四种流布局、4/32/128 顶点和五种法线/切线模式，充分预热后交替运行旧/新 DLL，检查零分配；另用 packed-billboards 回归面片输出。基准不含 GPU，最终收益以同条件游戏报告为准。

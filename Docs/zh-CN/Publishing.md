# 明文资源构建管理器

[简体中文](Publishing.md) | [English](../en/Publishing.md)

Unity 菜单：`RimUnity / 明文资源构建管理器`。通过本地 UPM 包安装时，窗口直接使用包内源码，无需复制脚本到 Assets。

配置保存在制作项目的 `ProjectSettings/RimUnity.json`，UI 标记保存在 `ProjectSettings/RimUnityWindow.json`。首次打开无需配置文件；在“构建设置”设置内容仓库、ShaderTool、游戏目录和 AB 标签对应的 Mod 根目录，然后保存。项目配置不应提交到 RimUnity 框架仓库。

入口来自配置的 AB 标签和手动加入的资源；贴图、材质、Shader 和动画依赖自动收集。输出位置为目标 Mod 根目录下的 `1.7/Data/RimUnity`。报告写入制作项目的 `Library/RimUnity/Reports`。

完整重建包含当前配置中的入口，会在全部目标完成导出与结构验证后替换旧数据；希望保留其他入口时使用“导出选中”。搜索和问题筛选只影响列表显示，不限制导出范围；不想发布的资源需移出 AB 标签或手动入口。检查失败、导出失败或准备阶段取消不会替换正式数据。发布阶段失败会恢复此前版本。结构验证不代表游戏内视觉验收通过。

同一目标 Mod 的入口在同一批次导出，按资源 ID 复用贴图、材质、网格和 Shader 变体。发布前自动只保留清单入口及其依赖，去掉未引用的历史文件；内容相同的附属文件存入 `blobs/`，只保留一份。局部发布也会整理目录，但保留未重新导出的公开入口。

清单和小型配置保持明文。超过 4 KiB 的 Prefab、Mesh、AnimationClip、RuntimeAnimatorController JSON 在压缩有效时保存为 `.json.gz`，游戏直接流式读取；用常见 Gzip 工具即可还原 JSON。省略缩进和 null 字段，保留显式零值、false、粒子参数与资源精度。文件去重不会合并不同资源 ID 的对象身份，也不会降低贴图分辨率。单个导出窗口与逐项粒子导出保留明文和历史目录；这些结果可用[发布副本 API](ResourceLoading.md#发布内容资源)整理后再分发。

多个模组共同发布时，构建管理器按 `About/About.xml` 的 `modDependencies` 和 `modDependenciesByVersion/v1.7` 复用必需依赖中的相同文件。依赖必须在同一批发布目标中；不会从无依赖关系的模组借用资源。`catalog.json` 的 `sharedFiles` 记录相对文件名与所属 packageId；依赖必须安装并启用，缺失时会明确报错。请将共享资源的主模组与扩展作为配套版本发布；主模组重新构建时，一并构建使用它的扩展。

压缩发布清单使用 `formatVersion: 2`，需要 RimUnity 0.1.7 或更新版本；旧运行时不能加载。PrefabLoader、AssetLoader 和脚本逻辑路径无需改变。

0.1.8 新增逐文件 GPU 贴图无损压缩：有足够收益的 `.rutex` 保存为 `.rutex.gz`。这类输出需要配套的 0.1.8 运行时，旧贴图仍可读取。只影响磁盘存储与首次读取，不降低分辨率、不修改 GPU 块或增加每帧解压。已有资源可通过离线整理生成压缩副本，无需启动 Unity 重导。

缺失脚本会作为警告写入预制体，游戏载入时会报告；其他可导出组件仍可使用。Shader Graph 和需要另行编译的脚本资源会在列表中提示，移出这些入口后即可导出其余内容。

## 构建设置与导出日志

“构建设置”按内容包输出位置、导出设置、制作工具链分区。内容过长时可滚动，底部“保存配置并刷新检查”始终可见；编辑后需要保存才会写入工程配置。

“导出日志”左侧按时间列出每次打包或导出，并标记全量／增量和成功／失败／取消。选中后右侧提供概览、涉及资源、输出资源、执行详情：包括起止时间、耗时、目标绝对路径、本次入口及自动依赖、发布后的资源清单与实际文件、共享文件所属模组及原始执行信息。增量的输出清单包含保留的旧资源；失败或取消不把旧清单冒充本次成功输出。

最近 50 次记录自动保存在工程的 `Library/RimUnity/Reports/export-history.json`，重开窗口后仍可查看；清理 Library 会同时清除历史。输出详情保存的是导出当时的快照，后续导出不会改变旧记录。可在底部复制或保存选中的完整记录，保存后直接定位文件。旧版逐行日志不会自动转换成历史条目。

## Renderer 导出设置

窗口的输出与工具配置页提供四个独立选项：自动关闭 Cast Shadows、接收阴影、光照探针、反射探针。默认均关闭；保存到制作项目的 `ProjectSettings/RimUnity.json`。开启的选项仅作用于导出副本，记录资源、层级、组件及原值。源 prefab 和模型资源不保存修改；反射探针开关不改变材质的 Cubemap。关闭开关时仍执行原有严格检查。

程序调用可使用 `PrefabExporter.Export(modDirectory, new ExportOptions { disableCastShadows = true }, requests)`。原有 Export 重载保持严格模式，不使用静态全局开关。

## AB 包筛选与重复资源归属

“资源清点”左侧显示项目 AB 包及已配置的空包，右侧为扁平资源表，包含入口和自动引用的材质、贴图、Shader、网格及动画依赖。每行显示小预览、类型、AB 归属、输出模组、源文件大小与状态；同一路径只显示一次，共享资源仍可在引用它的包下找到。自动依赖不会被误记为未归属。

可按包、类型、UI 状态（全部／UI 资源／非 UI 资源）、共享状态、检查问题及名称/路径筛选，单击表头排序。大小是源文件体积，不等于导出体积或显存。小预览按可见行加载。复选框、Ctrl/Command 多选与 Shift 连选都可使用，双击资源定位到 Project。

选中一批资源，直接拖到左侧目标 AB 包，或在底部选择目标后点击“迁移归属”。也支持把 Project 中的 Assets 资源拖进目标包。没有输出映射的现有包会建立空映射，发布前仍需在构建设置填写目标目录。Packages 中的资源可查看，不修改其标签。

左下角“新建 AB 包”可建立空包与输出映射，随后拖入资源。底部“加入 Project 选择”保留手动添加入口的方式。

每行“UI”列的复选框明确标记该资源是否为 UI 资源，自动依赖也可独立标记；多选后可用底部“UI 资源”批量修改。修改立即保存到工程的 `ProjectSettings/RimUnityWindow.json`，重开窗口仍保留。勾选材质或 Shader 后，包括自动引用的依赖在内，实际导出会按 UI 模式处理；其他类型的标记用于分类，不改变 Prefab 原有的 Canvas 自动识别。标记不会把依赖自动注册成独立导出入口。UI 状态筛选可与其他筛选组合。 勾选 Shader 为 UI 时，所有引用该 Shader 的材质都按 UI 模式导出；如果同一个 Shader 同时用于世界和 UI，请只标记对应的 UI 材质。

筛选只影响显示。底部只保留“导出选中”和“完整重建”，不再提供增量模式选择。“完整重建”处理整个配置清单，不受筛选限制。“导出选中”保留其他已发布入口；选中已注册入口时只提交这些入口，不自动扩展其他引用者；选中没有独立注册的自动依赖时，仅补充仍有更改的直接或间接引用入口，确保各个变体按原上下文更新。窗口底部提前显示“已选多少项／实际导出多少个入口”，日志也记录这两个数量。没有引用入口的资源仍可独立导出，但跨包资源需先明确唯一归属。发布的检查、事务和失败回滚规则保持不变。

在下拉框中选择任意已配置目标包，点击“迁移归属”。此操作修改源资源的 AB 标签，注册目标包入口，并将归属记录保存到 ProjectSettings/RimUnity.json 的 resourceOwners。下次完整发布时，资源的各导出变体、描述文件和载荷只存于目标模组；其他模组保留清单记录和共享文件引用。不同变体的内容及资源 ID 保持不变。多个 AB 包对应同一模组时共用该模组的存储。

显式归属不要求 About 声明依赖，也不会自动添加依赖或调整加载顺序，这些由使用者维护。运行时目标模组未启用会报告缺失依赖。“取消指定”只撤销导出归属策略，不会恢复此前的 AB 标签。增量发布可解析迁移后的共享描述，但首次迁移后应完整发布，以清理上一版残留。

## 仅显示有更改

勾选“仅显示有更改”，可与类型、UI 状态、包、搜索等筛选组合。表格状态显示“有更改”或“已同步”，悬停可查看原因。筛选后使用表头复选框选择可见资源，再点“导出选中”。“完整重建”始终覆盖所有配置入口。

成功基线保存在制作工程的 Library/RimUnity/export-baseline.json。首次启用、基线丢失或损坏时，所有未确认的资源均显示为有更改，需要成功导出一次建立基线；不能从旧产物倒推当时源资源的状态。源资源通过 [Unity 依赖哈希](https://docs.unity3d.com/ScriptReference/AssetDatabase.GetAssetDependencyHash.html) 检测，包含递归引用、源文件、导入设置、meta、平台和导入器版本。贴图、材质、Shader 或动画等自动依赖变化会标出依赖本身和所有受影响入口。移除或替换引用也会标出入口。

UI 标记、Renderer 导出设置、目标映射、共享归属、About 依赖声明、Unity/导出器版本、ShaderTool 及同目录 DLL/JSON/config、游戏宿主程序集变化也参与判断。部分公共设置变化会保守标记全部入口。输出按入口遍历依赖描述和真实载荷，包括 gzip 描述和跨模组共享文件；缺失或内容变化会标出入口。仅移动同内容的导出目录不会反复触发变更。

基线按入口分别记录，只有整次发布成功后才更新本次入口，失败或取消保持原基线。共享依赖只更新一个引用入口时，其他未更新入口仍显示有更改。扫描在刷新清点、资源导入和 UI 标记修改后请求，连续请求会合并。切回窗口优先复用已有列表；当前选中资源未保存时会请求重查。外部工具或输出文件改动后可点“刷新清点”主动检查。未保存的材质、Prefab 等资源会明确提示“源资源尚未保存”；建议先保存，再导出。Shader 的编辑器 dirty 标记也可能来自内部编译状态，因此 Shader 只按源文件、meta 和导入依赖哈希判断，不因 dirty 标记单独误报。

资源清点通过编辑器更新回调在主线程分帧执行，不创建后台线程。顶部显示进度百分比和当前阶段，悬停可查看正在处理的路径，并提供“取消”。每次更新以约 8 ms、最多 24 个步骤为推进预算，大文件哈希按 128 KiB 分块。单次 Unity 资源查询、JSON 解析或第三方处理器调用仍可能超过预算，不能在执行中强行中断。

扫描期间保留上次完成的列表，可继续查看、搜索和选择；导出、设置修改、UI 标记和归属修改暂时禁用。新结果完成后统一替换。扫描期间发生新的资源变更会丢弃旧任务并合并重查；取消、失败、关闭窗口或脚本重编译都会释放扫描和文件句柄，不更新成功基线。取消后需重新刷新并完成扫描，才可导出。

自动发现的自定义处理器可以实现 IExportChangeFingerprint.GetChangeFingerprint()，返回涵盖全部外部输入和配置的稳定字符串。声明不读取外部状态的处理器可返回固定版本字符串，修改行为时同步升级版本。未实现接口、返回 null 或抛异常时，相关入口始终保守显示为有更改，防止遗漏动态读取的外部文件。修改脚本代码也会因程序集版本变化而触发检查。删除已不再配置的旧入口，仍需完整重建相应目标进行清理。

## 四维 UV 与浮点数据贴图

网格通过 `uvChannels` 保存最多八个四维 UV 通道，保留用于顶点动画的 Z/W。旧的 `uv`、`uv2` 等二维资源描述仍可读取。源 Mesh 身份、子网格和材质归属不变。

RHalf、RGHalf、RGBAHalf、RFloat、RGFloat、RGBAFloat 贴图以 `numericFormat=RGBAFloatLE` 保存四通道小端浮点载荷，保留负数、超出 0–1 的值及精度。半精度值可无损扩展到 Float32。导出从 Unity 导入后的贴图读取，非可读资源需真实图形设备；保存的行方向与宿主采样一致。旧 PNG 资源仍按原路径读取。新增格式需要配套的新运行时，已损失通道或精度的旧资源必须重新导出。

制作项目没有 TextureImporter 的 `.asset` 贴图根据 `isDataSRGB` 判定编码，避免把线性动画数据当作颜色。运行时绑定材质或全局贴图时同步 `_TexelSize`，因此顶点 Shader 可使用正确的宽高和倒数。

## 游戏内特效诊断

进入地图并开启开发模式，在调试操作菜单搜索“粒子渲染诊断”。面板支持 ParticleSystemRenderer、MeshRenderer、LineRenderer 与 TrailRenderer，筛选实例，暂停采样，复制当前或全部报告，也可导出文本。

诊断只在面板开启时采样，最多 256 条实例/材质快照；关闭后清空文本状态，不保留游戏对象。报告涵盖材质、UV、纹理、最终绘制资源以及动画 Uniform，但不是 GPU 像素读回，不能单独证明画面渲染正确。浮点数据贴图与网格可用后仍需实际动画验收。

局部发布只对计划入口及其依赖执行序列化，不会先序列化全部入口再丢弃。旧产物准备阶段直接复制文件，最终仍会整理整个目标清单、压缩/去重并校验，因此还存在与选中数量无关的固定成本。目前没有逐资源复用已序列化依赖的完整缓存。执行日志分别记录准备旧产物、序列化入口、整理最终产物的耗时，便于区分瓶颈。

# 显存归责窗口

开发者菜单 → RimUnity → **显存归责（全量分配）**。主菜单和地图内均可打开。

打开时采集一次；之后按“刷新快照”重新读取。不在 Tick 或每帧绘制中扫描资源。选择左侧来源查看该组全部资源，右侧可按路径、类别、来源搜索。两侧列表均仅绘制可见行。悬停资源查看完整路径、字节数、唯一句柄与来源证据；悬停汇总查看采集限制。复制全量 JSON 不受当前筛选影响。

## 统计口径

- 使用宿主 `GpuMemoryTracker.CollectAll` 的完整分配快照，不截取最大 150 项。每个 `(image/buffer, Vulkan handle)` 只计一次，出现重复句柄则拒绝生成新快照。
- 按启用模组的实际内容根目录识别来源，优先原始文件路径，其次分配标签的完整内容目录前缀。不通过短文件名猜测。相同目录名、冲突来源、相对路径跳转保留未归属。
- 归属表示**资源提供方**，不是触发加载者，也不是卸载模组能够节省的字节数。HAR 触发加载的原版资源不计给 HAR。原版 `Resources/` 标签不足以细分 DLC 时合并显示。
- 混合图集、动态网格、通用缓冲等缺少模组来源的分配单列“共享 / 动态资源（未归责）”，不等分、不按对象数量分摊。没有证据的普通纹理单列“未归属”。
- 纹理通过 Vulkan 图像句柄关联宿主分配注册表，依据 `IsHostResident` 区分非设备本地内存和设备本地内存。不能确认的分配（包括多数缓冲区）显示“位置未知”。三种位置之和等于分配总字节，不把未知加进显存。
- **设备本地分配不等于驱动实际物理驻留。** 驱动可能做内存分页。窗口另列各堆驱动使用量和预算、VMA 分配与块预留；不能将其差额归给某个模组，不能将不同口径相加。
- 已缓存但尚无 GPU 分配的 RimUnity 纹理不计分配字节；窗口说明中的数量是缓存引用数量，不代表全游戏未上传纹理总数。

## 观察安全与兼容

采集在游戏主线程由用户触发。读取注册表时使用宿主自己的 `System.Threading.Lock`；不调用强制 GC、上传、恢复纹理、驱逐、设备空闲或渲染设置修改。宿主注册表通过反射只读访问；接口变化时退回标签证据或未知位置，并在快照 Notes 中说明。不是 GPU 同步原子快照，预算与资源分配依次读取。

窗口只保留字符串、数值和时间，不保留纹理、地图、Pawn 或 GPU 分配对象。关闭窗口即释放快照引用，无新增存档状态或全局采集回调。

## 验证

`Tools/MemoryAttributionTests` 覆盖来源边界、重名目录、相对跳转、共享图集、原版来源、超过 150 项的全量对账、位置未知字节守恒和全量导出，并可对当前游戏程序集检查只读注册表接口：

```powershell
dotnet run --project Tools/MemoryAttributionTests -- 'D:\SteamLibrary\steamapps\common\RimWorld'
```

游戏内检查：空地图采集一次，触发特效后刷新，结束后再刷新；检查来源明细和内存位置变化。关闭开发者模式后窗口应关闭。UI 缩放和中文长路径需要在游戏内检查，不能由编译验证替代。

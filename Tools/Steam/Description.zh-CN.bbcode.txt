在 Unity 2022.3 中打开 Window → Package Manager → + → Add package from tarball，选择下载的 TGZ 即可安装。工具供模组作者使用，普通玩家只需启用游戏模组，无需下载工具或安装 Unity。当前为预览版，支持范围见下文。

RimUnity 是面向 RimWorld 1.7 的资源与表现框架。模组作者可以在 Unity 中制作粒子特效、预制体、材质、界面、模型和动画，通过配套导出工具转换为明文资源，再由游戏的 Waylith 引擎加载和运行。

[b]对于玩家：[/b]这是供其他模组使用的前置框架。本体不添加种族、建筑或武器；启用依赖它的内容模组后，才能看到对应效果。玩家无需安装 Unity 或导出工具。

[b]对于作者：[/b]继续在 Unity 编辑器里搭层级、调粒子、配置材质和绑定脚本字段。游戏侧使用 RimUnity 的对象与组件 API，将效果接到建筑、角色、技能和界面逻辑中。

[h2]为什么使用 RimUnity？[/h2]

[img]https://raw.githubusercontent.com/chezhou9413/RimUnity/main/Tools/Steam/Images/zh-CN/advantages.png[/img]

[list]
[*][b]保留熟悉的制作方式。[/b]使用 Unity 原生组件制作资源，在编辑器中调整效果，减少在游戏代码里手写层级和参数的工作。
[*][b]依赖自动收集。[/b]导出器处理嵌套 Prefab、Variant 及材质、贴图、网格、字体、动画等依赖，支持单个预制体、批量粒子和资源构建管理器。
[*][b]熟悉的编程接口。[/b]提供 GameObject、Transform、MonoBehaviour、Instantiate、GetComponent、Play、Stop 和协程等常用接口。调整类型引用并重新编译后，可以沿用相近的脚本组织方式。
[*][b]资源可读、目录清楚。[/b]预制体、材质和动画数据以 JSON 保存，Shader 使用 GLSL。每个内容模组拥有自己的资源目录，按稳定逻辑路径加载，方便版本管理和排查问题。
[*][b]材质随资源接入。[/b]自动处理支持范围内的材质参数、纹理和 Shader 转换，无需为每个导出材质单独手写 ShaderDef。
[*][b]可控的发光表现。[/b]支持 Linear 资源的地图 HDR 透明混合，以及按 Layer 筛选的 Bloom；内容模组可以将泛光接到自己的设置开关。
[*][b]开源且可扩展。[/b]框架及配套导出工具采用 MIT 许可证，可查看源码、修改和参与完善。
[/list]

[h2]可以用来做什么？[/h2]

[list]
[*][b]粒子与特效：[/b]循环和爆发发射、曲线与渐变、图集、子发射器、拖尾、自定义数据、力场，以及受限碰撞和 Trigger。
[*][b]材质与 Shader：[/b]常见 Unlit、透明和加法材质，以及支持范围内的 UV 动画、遮罩、溶解等自定义顶点／片元程序。
[*][b]界面：[/b]常用 UGUI 控件、布局、指针事件、Text、基础 TMP SDF 文字，以及 IMGUI 自定义材质绘制。
[*][b]模型与动画：[/b]静态／骨骼网格、基础 Animator、1D 混合、属性动画、动画事件、LineRenderer 和 TrailRenderer。
[*][b]脚本与层级：[/b]预制体实例化、父子节点、字段与事件引用、Mono 生命周期和常用协程。
[/list]

[h2]玩家如何使用[/h2]

[olist]
[*]使用 Windows x64 的 RimWorld 1.7。
[*]安装并启用 Harmony、RimUnity，以及需要它的内容模组。
[*]加载顺序保持为 Harmony → RimUnity → 对应内容模组，并遵守内容模组自己的其他依赖要求。
[*]按内容模组的说明使用特效。RimUnity 的地图 Bloom 默认关闭；需要时在模组设置中配置，或使用内容模组提供的开关。
[/olist]

[h2]作者如何接入[/h2]

[img]https://raw.githubusercontent.com/chezhou9413/RimUnity/main/Tools/Steam/Images/zh-CN/workflow.png[/img]

[olist]
[*]从上方链接下载 UPM TGZ，在 Unity 2022.3 LTS 的 Package Manager 中选择 Add package from tarball 安装；制作端支持 Built-in 与 URP 14 的指定功能。
[*]制作资源，通过 RimUnity 导出窗口或构建管理器导出到自己的内容模组。
[*]游戏侧引用 RimUnity.Core.dll 和 RimUnity.dll，使用 .NET 10 编译自定义脚本，并声明 RimUnity 依赖。
[*]使用 PrefabLoader.Load 获取模板，再调用 RimUnity.Object.Instantiate 创建实例。将导出的清单与全部依赖随内容模组一起发布。
[/olist]

运行时加载的是 RimUnity 导出的资源，不读取原版 Unity 二进制 AssetBundle。已有 AB 标签可以用于组织导出入口，资源仍需经过导出工具处理。

[h2]资源复用与性能机制[/h2]

[img]https://raw.githubusercontent.com/chezhou9413/RimUnity/main/Tools/Steam/Images/zh-CN/performance.png[/img]

导出时裁剪未引用依赖、压紧 JSON、压缩大文件并复用相同内容文件；加载时按逻辑路径和资源 ID 查询，复用模组内的依赖对象。图中展示优化机制，不是 FPS 跑分。压缩有解压成本，实际帧时、内存和加载收益取决于资源与场景，尚无统一性能对比数据。

[h2]支持范围[/h2]

RimUnity 提供明确范围内的 Unity 风格功能，不能直接运行任意 Unity 项目或未适配的第三方 DLL。自定义脚本需要使用游戏侧类型并重新编译。

目前不支持 Shader Graph、Live2D、Humanoid／IK、完整 Unity 光照与后处理栈。物理为简化实现，地图粒子 Lights 用于格子照明；原版建筑和 Pawn 不会自动成为碰撞体。随机粒子轨迹、部分渲染参数与最终画面可能与 Unity 存在差异，具体效果需在游戏中核对。

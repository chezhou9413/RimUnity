# 批量构建与发布

## 什么时候使用构建管理器

单个 Prefab 用导出窗口即可。多个 AB 标签、独立材质、多模组输出和共享资源归属，用 RimUnity → 明文资源构建管理器组织。

资源清点页左侧选 AB 包，右侧用扁平表格查看小预览、类型、归属、输出模组和源大小。复选或按 Ctrl/Command、Shift 多选后，拖到左侧目标包即可迁移归属；也可以拖入 Project 中的资源。左下角可新建空包。源大小只表示工程文件体积。

表格同时列出自动依赖。共享资源仍会出现在引用它的包中，但只保留一行。类型、共享和问题筛选可以组合使用，表头可排序。双击资源可定位到 Project。

“构建并导出”处理整个配置清单；“导出选中”仅以选中的资源为入口进行增量导出。未指定唯一归属的跨包依赖，应先迁移到目标包，再独立导出。

AB 标签在这里是资源分组信息，导出产物仍是明文数据。它不会生成旧式二进制 AssetBundle。按 AB 导出的入口可以通过包名和原工程路径加载；批量粒子窗口使用 Particles 开头的逻辑路径，最终以 catalog 为准。

## 推荐工作顺序

1. 确认目标模组和 ShaderTool 配置。
2. 扫描入口，检查资源类型、重复引用及失败项。
3. 明确共享资源属于哪个内容模组。显式归属不等于自动声明模组依赖，需要自行维护 About。
4. 执行导出。导出器递归收集引用，同一事务内共享材质、贴图等依赖只写一次。
5. 检查游戏表现，再发布完整清单和所有可达依赖。

catalog 是提交点。某个入口导出失败时保留诊断和旧成功清单；不要把失败工作目录中的文件当作新发布版本。按入口提交的批量任务可能同时包含成功和失败项，应查看构建报告。

## 查看每次导出

“导出日志”左侧按时间列出导出记录，选中后右侧查看概览、涉及资源、输出资源和执行详情。概览包含全量／增量、结果、耗时与目标路径；资源页列出本次入口及自动依赖，输出页列出最终资源清单、实际文件和共享归属。增量输出也包含保留的旧资源。

失败、取消也会留下记录，但不会把此前的输出当作本次成功结果。最近 50 次记录保存在工程 Library 下，重开窗口仍可查看；后续导出不会改写旧快照。底部可复制或保存选中的完整记录。

## Renderer 导出设置

构建设置可关闭导出副本上的投影、接收阴影、Light Probes 和 Reflection Probes。源 Prefab 保留原值。只关闭确实不需要的功能，并检查实际视觉效果。

## 更新与交付

交付内容模组的 1.7/Data/RimUnity 及自己的游戏侧程序集。不要分发 Unity 工程缓存或从游戏引用的 DLL。共享归属首次迁移后应完整发布，以清理旧输出残留。

新增百科全书与处理器不需要重新编译游戏运行时。修改了导出的内容后，需要重新导出，并重启游戏刷新加载缓存。

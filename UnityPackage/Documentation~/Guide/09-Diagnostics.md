# 诊断与排错

## 导出失败

先读 Unity Console 与输出工作目录的 FAILED.txt。错误通常包含资源路径和具体不支持的组件、Shader 或设置。当前事务失败不会替换旧成功清单；批量任务仍应检查每个入口的状态。

先用一个最小 Prefab 重现，再逐项加入组件。Shader 转换时核对工具路径、目标游戏目录、关键字和材质状态。处理器报错时，汇总异常还会保留清理失败信息。

## 游戏加载失败

依次核对内容模组是否启用、owner/packageId、逻辑路径、完整清单依赖和配套程序集。逻辑路径与文件路径不同；自动收集的内部资源不一定是可直接加载的公开入口。

导出文件更新后重启游戏。运行时不会自动热重载 catalog 或已经缓存的模板。

## 有特效但显示不正确

在地图开发菜单打开 RimUnity 的粒子渲染诊断。先清空记录，再只触发目标效果，按实例名筛选，暂停采样后导出报告。

报告可以核对实际材质、UV、纹理、Uniform 及最终绘制资源。采到另一种特效时不能拿来证明目标资源的问题；资源存在、GPU 已分配也不等于最终像素正确。

## 卡顿、显存或场景问题

首次特效卡顿采集会记录有限时间内的帧、事件和资源状态。先开始采集，再触发一次效果，比较首次和后续调用。GC、线程分配和跨线程事件有不同测量边界，不能简单累加重叠事件作为总耗时。

一次性场景与显存诊断包含环境、Vulkan 设备、分配、资源、绘制、程序集与近期日志。查看报告中的截断和未命中提示。根据具体症状选择对应工具，不必每次收集全部报告。

原文区保留三个诊断专题和显存归责说明。

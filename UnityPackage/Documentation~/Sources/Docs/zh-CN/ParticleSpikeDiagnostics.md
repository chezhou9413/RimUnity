# 首次特效卡顿采集

开发者菜单中搜索 `卡顿诊断`，所有入口位于 `RimUnity` 分类。适用于首次生成某个粒子特效时的瞬时卡顿，也可以在主菜单采集。

## 特效性能测试场

在已加载地图的游戏中启用开发者模式，打开调试动作菜单的 **RimUnity → 特效性能测试场**。工具会建立 96×96 的临时棋盘地图并暂停原版游戏 Tick；不需要额外 DLC。

测试地图使用无动植物的专用生态，保持晴天和 21℃，不依赖世界地块的植物生长率采样。相机和控制面板在地图绘制初始化后开启；创建失败会先记录原始异常，再清理临时地图已经建立的资源。

带有缺失脚本等导出警告的特效会在选择列表中标明原因；选中资源的原始警告写入 TXT、JSON 报告的 `AssetWarnings`。其脚本行为可能不完整，性能结果不能视为完整源特效的性能。Animator 遇到当前预制体不存在的动画节点或组件时，只跳过这些目标的曲线并按剪辑去重提示，保留有效轨道；补齐层级后可调用 `Rebind()` 重新绑定。这不会恢复源资源中已经缺失的节点或脚本。

1. 在“选择特效”页按模组名或逻辑路径筛选，勾选要测试的特效。只索引已启用模组中含 `RimUnity.ParticleSystem` 的导出预制体，读取描述时不会提前实例化或加载贴图。
2. 在“播放控制”页设置并发上限、每秒播放次数、实例最长寿命、分布半径、整体倍率和 X 轴旋转。选择一个特效时循环播放，选择多个时按列表顺序轮播。缩小分布半径可以提高画面重叠密度。
3. 点击“应用参数并播放 / 重新开始”。测试实例使用真实时间，保留原有子发射器关系、预热和材质。参数重新应用时先导出旧样本、清理实例，再开始新一轮。
4. 在“采样与报告”页调整采样时长，或停止、重新采样、导出。默认 60 秒，可调 10～300 秒；固定最多保留 36000 帧，到时或达到容量会自动停止并导出。采样停止后可以继续观看特效。
5. 可折叠控制面板，减少界面绘制对测量的影响。关闭窗口、退出开发者模式、切换地图或离开游戏会话会停止测试和采样；正常关闭返回原地图并删除临时地图。测试期间不能保存，退出后恢复保存功能。

常规报告保存在游戏配置目录的 `RimUnityReports`，文件名前缀为 `effect-lab-`：

- `.txt`：测试条件，平均帧率，P50/P95/P99/最大帧间隔，慢帧数量，托管分配、GC、工作集变化，以及各资源实例创建的首次、平均、最大耗时。
- `.json`：测试参数、所选资源、程序版本标识、完整逐帧样本与按资源汇总的创建耗时。
- `.frames.csv`：逐帧时间、进程分配、GC、测试实例/系统/粒子数、地图提交项、内存、实际创建数、限流帧数及详细探针开关状态。

“开启详细耗时探针（60 秒）”复用下文的卡顿诊断，生成独立的 `particle-spike-` 报告，用于区分加载、生命周期、预热、模拟、网格和上传耗时。离开测试场会停止由测试场启动的探针。常规采样会标记详细探针开启的帧，避免把探针自身的开销误认为性能退化。

播放器每帧最多创建 16 个实例，并在已耗时 8ms 后暂停本帧继续创建；单次实例化不可中断。达到预算后不追赶积欠发射，报告会记录实际创建速率与限流帧。并发上限和实例寿命也会限制实际密度，报告中的请求频率不能直接当作实际频率。

帧间隔、托管分配和内存包含整个游戏、其他模组与采样本身的开销；粒子数量只统计测试实例。地图提交项不是驱动实际 DrawCall，未测量 GPU 执行时间或显存。第一条间隔可能不足整帧。测试场复用进程资源缓存，不保证每轮都是冷加载；已经加载的其他模组及真实时间脚本也可能影响结果。场地中的预制体仍执行自己的脚本，测试结果应结合所选内容判断。

测试场未启用时不注册播放和采样回调，也不安装测试场计数补丁。既有“卡顿诊断”手动采集入口保持独立，只有用户显式开启时才运行。

### 绘制合批与报告

完整特效实例的创建、复位与回收由上层模组作者管理。RimUnity 不提供预制体实例池，测试场持续走正常 Instantiate/Destroy 路径，确保创建与销毁成本进入报告。

世界粒子提交按原顺序合并相邻的兼容段，可跨粒子系统和预制体实例。必须使用同一材质对象、同一图层、单个 Shader Pass、无实例参数覆盖，而且程序已在资源加载时完成合批兼容检查。每批最多 65536 顶点、196608 索引；遇到不兼容项或容量边界立即提交。带多 Pass、存储缓冲、场景抓取、原生顶点/实例/图元编号或未检查程序的绘制保持独立。不会跨越不同材质去重排透明物体，交错材质的合批收益可能较小。

合批直接追加已有世界坐标和顶点流，不合并或延长 GameObject 生命周期，也不改写模拟时间。每个相机及连续段使用独立动态网格，同帧提交后不再次覆盖；峰值后的闲置尾槽会回收，读档和退出图形设备时全部释放。保留已有逐粒子排序、UV、颜色和自定义顶点流。UI 粒子以及显式的粒子材质诊断快照使用独立提交。

常规报告 schema 3 新增 `ParticleDrawsBeforeBatch` / `ParticleDrawsAfterBatch`，TXT 汇总前后数量及减少比例，CSV 对应 `particle_draws_before_batch` / `particle_draws_after_batch`。这些值统计本帧经过世界粒子绘制入口的所有相机，包含不兼容项的独立 Pass；不包含普通 MeshRenderer、UI 或 HDR/Bloom 再绘制，也不是驱动实测 DrawCall。仅在常规采样开启时累计。详细探针的 `Particle.BatchFlush` 标记合并网格提交，原有单 Renderer 绘制计时不再包含延后的整批上传。

对比旧报告时保持特效集合、并发、频率、寿命、视角与 Bloom 相同，关闭详细探针，使用相同采样时长。先播放至少一轮最长寿命，再单独开始常规采样，可以比较稳定阶段；从“应用参数并播放”开始则包含首次创建成本。合批数量下降不等于帧率按同比例上升，粒子模拟、像素覆盖和其他模组仍占用时间。

粒子固定顶点布局按顶点连续写入上传缓冲；HDR 派生绑定按源材质版本、参数版本与管线状态缓存，参数变化时生成新绑定，保留在途快照的旧状态。动画访问器按类型与属性路径共享，不保留场景对象；首次遇到属性仍需编译。每个粒子系统的空闲拖尾缓存限制为 32 个容器、合计 1024 个采样点容量；HDR 标记集合最多保留 8 份、单份容量不超过 16384，归还时清空绘制引用。

普通网格预制体和蒙皮网格仍按各自的 MeshRenderer 提交；本轮跨实例合批覆盖的是预制体中的粒子绘制，没有把 Shader 的 `enableInstancing` 标记当成已接通 GPU 实例化，也没有改变模拟精度或转为 GPU/Burst 模拟。

## 复现一次并导出

1. 如果要测冷启动，先重启游戏。已经加载过的资源不会因开始采集而变冷；工具不会清空游戏的 Shader/纹理缓存。
2. 关闭其他持续采样的诊断窗口，进入准备触发特效的场景。
3. 点击 **卡顿诊断 1 · 开始采集（60秒）**。复杂复现场景可用 120 秒入口。
4. 关闭开发菜单，空等两三秒取得空闲基线。
5. 触发特效一次；等它稳定后，再触发同一特效一次。尽量保持相同视角、位置和游戏速度。
6. 点击 **卡顿诊断 3 · 停止并导出**。不手动停止也会到时自动保存。

可选用 **卡顿诊断 2 · 添加触发标记** 区分几次操作。标记写入后再关闭菜单并触发特效；菜单本身会影响帧间隔。

完成后会在游戏配置目录的 `RimUnityReports` 子目录生成四个同名前缀的文件，并复制文本报告路径到剪贴板：

- `.txt`：可直接阅读。含测量边界、最慢帧、重叠事件、首次与后续调用、探针覆盖和前后资源状态。
- `.json`：完整的已保留事件、全部聚合统计、帧样本、上下文与探针覆盖。
- `.events.csv`：可按时间、线程、资源或父调用 ID 筛选的事件。
- `.frames.csv`：所有已保留的主循环帧间隔、分配增量、GC 次数和粒子数量。

“再次导出上次报告”用于重新保存内存中的最后一份采集，包括导出失败后的重试；开始新采集会替换它。关闭开发者模式、切换游戏会话或关闭图形设备也会结束采集。报告不会写入存档。

## 采集覆盖

- 清单查找、资源缓存命中/未命中、JSON 文件打开与反序列化、资源载荷加载、模板构建、实例对象图构建与字段绑定。
- 自定义 Shader 加载、标准粒子变体、Linear/HDR 变体、宿主编译和编译缓存标记、磁盘 Shader 缓存读取、Shader Module 获取。
- 纹理加载、缓存读取/图片解码、首次驻留、像素上传、设备纹理分配、上传提交、纹理驻留腾挪。
- 脚本生命周期队列、回调、首次绑定生命周期委托、脚本异常。
- 粒子播放、重置、整组模拟、预热、物理扫描、粒子和拖尾绘制、网格提交、宿主网格上传。
- 宿主图形管线获取、主线程整帧事件、渲染线程整帧事件，以及桥接 Bloom/HDR 阶段。
- 帧间隔、当前线程托管分配、进程分配增量、进程 GC 次数；资源缓存和活动粒子配置的采集前后快照。

本机宿主有几个方法包含当前 Harmony 无法安全改写的只读引用调用。工具使用宿主帧事件和自有方法的直接计时代替改写 `FrameRenderer.CaptureFrame/RecordFrame`、`CompositePass.Record`、`GpuTextureService.CreateTexture2D`。这些覆盖差异会列入报告，不会静默当作零耗时。

## 怎么读报告

先看“采集完整性”和“探针覆盖”，再看“最慢帧间隔及重叠事件”。`OK` 表示探针安装成功，不代表目标调用一定经过该入口。

`Asset.Get` 的 `cache=miss` 表示资源模板缓存未命中；`cache=hit` 表示资源对象已经存在。`Shader.Compile` 的 `compilerCacheHit=True` 是宿主返回的缓存标记；False 也可能来自宿主覆盖文件分支，需结合 `Shader.CompileMiss` 是否出现判断是否实际编译。`Texture.ReadDecode` 的 `textureCacheHit` 是宿主纹理缓存标记。`Texture.FileResident` 会记录调用前是否已有设备资源和 CPU 像素。

`Prefab.Build | instance` 是实例对象图构建，Awake/OnEnable 还可能在外层实例化事务结束后发生，单列为 `Lifecycle.Drain/Callback`。按时间线一起检查，不能把对象图构建时间当作整个 Instantiate 的时间。

粒子组事件会记录待预热根数量、模拟时间跨度及粒子数，实例事件会记录容量、上限、duration、speed、碰撞、拖尾等配置。组内计数扫描最多 512 个系统；上下文最多列出 256 个活动系统。

`First/Second/Third` 始终是**本次采集最早观察到的调用**，不自动等于进程冷启动。`duration` 是包含子调用的 CPU 墙钟时间，`self` 扣除同线程、同会话内已测量子调用。嵌套 duration 不能相加，跨线程的耗时也不能相加当作帧时长。宿主帧事件是独立的外层时间段，不参与嵌套扣除；停止时的 partial main frame 只是部分帧。

所有 `GPU.*`、渲染帧和 Bloom/HDR 计时都是 **CPU 端调用耗时**。工具没有插入 GPU timestamp、像素读回或设备空闲等待，不能用它直接声称 GPU 执行耗时或精确呈现延迟。帧号是最近观察到的主线程桥接帧号；关联渲染线程时优先使用相对毫秒时间。

## 开销与限制

动态探针只在显式采集期间安装，停止时移除；自有 JSON 和渲染阶段的直接探针在未采集时只检查一个空会话引用，不分配对象。安装探针和读取上下文不计入采集时间，但安装过程与 JIT 仍可能影响冷启动条件。采集期间的反射、参数装箱、字符串、锁和记录分配会增加开销，因此本工具用于定位明显 spike，不用于证明微秒级性能改善。

每个 `stage + detail` 聚合全部已完成调用；事件保留最早三次、至少 2ms 的慢调用和异常。最多 4096 个聚合组、25000 条事件、12000 个帧样本。达到上限会显式报告丢弃数量；普通未保留调用仍进入聚合统计。父事件可能没有被保留。停止时还在运行的调用不补算为完整调用，报告列出未完成数量。

采集期间不写磁盘，停止后才导出。采集不会生成特效、清理资源缓存、强制 GC 或修改渲染设置。记录只持有文本和数值，不保留 Map、Pawn、组件或设备资源。用户目录会被替换为 `<USER>`；报告不收集存档内容、Shader 源码或贴图像素。

## 定向验证

`Tools/SpikeCaptureTests` 覆盖嵌套计时、异常、跨线程聚合、截断、会话隔离、快照隔离；可额外指定运行时程序集、游戏目录和 Harmony 路径，验证实际探针安装/移除、实际资源缓存入口和异常透传、out 参数缓存标记及导出结构。

首次使用仍应在游戏内按上述步骤触发两次特效，确认采集到目标资源及实际卡顿。离线测试不代替真实图形设备下的复现。
